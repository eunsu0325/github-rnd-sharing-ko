# 새 clone과 실행 검증

## 대상과 자원

문서/스킬 설치, 작은 offline 예제, SIM inference, GPU 학습, 실물 실행은 다른 작업이다. 요청한 공유 기능을 대표하는 작은 실행을 고른다. 공식 설치 경로를 먼저 사용하고 필요한 호환 변경은 이유를 남긴다.

로컬 편집→회사 GPU 실행→결과 회수라면 실제 환경·자원을 확인한다. 접속이나 자원이 없으면 가능한 준비를 계속하고 미실행 조건을 남긴다. 로컬에 무거운 스택을 임의 설치해 대체하지 않는다. 로봇 동작은 기본 설치 확인에 넣지 않는다.

## clone 확인점

- URL·repo·branch/tag/commit을 확인한다. 이력 없는 파일 폴더라면 특정 commit에서 왔다고 추측하지 않는다.
- 이미 checkout이 있으면 상태 확인과 동기화가 적절할 수 있다. 검증용 새 clone은 기존 작업과 독립 경로에 둔다.
- 필수 submodule은 기록된 commit으로 recursive clone/update하고 접근 조건을 확인한다. 재현 경로에서 `--remote-submodules`로 원격 최신 branch를 대신 받지 않는다.
- LFS는 pointer만 남지 않았는지 실제 파일 크기/해시 등으로 확인한다. 외부 자산은 존재·권한·revision·경로를 확인한다.
- ZIP을 지원한다고 안내하면 별도로 확인한다. 이력·submodule·LFS가 clone과 같다고 가정하지 않는다.
- 커넥터 접근과 팀원의 로컬 Git 인증은 다르다. HTTPS/SSH·credential helper·조직 접근 조건을 구분한다. 토큰을 대화나 URL에 넣도록 요청하지 않는다.

## 실행과 결과

가능하면 README 순서대로 설치/설정과 작은 실행을 수행한다. 버전 고정은 의존성 변화 영향을 줄이지만 OS/GPU/드라이버 재현을 보장하지 않는다. 개인 전체 환경 freeze를 검토 없이 공식 설치법으로 배포하지 않는다.

종료 상태와 예상 출력·결과 파일 내용·필요한 미디어 디코드·지표를 확인한다. 개인 캐시·설정·현재 폴더에만 있는 자산 의존성을 살핀다. 실패를 숨기거나 기능을 stub/mock 처리해 통과시키지 않는다.

실제 환경, 명령/설정, 코드·자산 revision, 결과 위치를 작업 크기에 맞게 기록한다. 최소 예제에 전체 실험 추적 플랫폼을 강제하지 않는다.

| 확보한 근거 | 표현할 수 있는 범위 |
|---|---|
| 파일/링크/원격 commit 조회 | 게시 내용·배포 경로 확인 |
| 같은 기계의 새 clone 실행 | 해당 기계·환경에서 최소 실행 확인 |
| 별도 의존성 환경/다른 기계 실행 | 실제 수행한 추가 환경까지 확인 |
| 설정·지표를 고정한 실험 비교 | 해당 조건의 결과 재현/차이 관찰 |
| SIM/replay/실물 실행 | 실제 수행한 종류·작업 조건만 확인 |

파일 전달·프로세스 시작·한 번의 수치 일치를 더 넓은 성능·재현성·실물 성공으로 확대하지 않는다. 제한이 있으면 부족한 조건과 팀원이 이어갈 위치를 적는다.

근거: [Git clone](https://git-scm.com/docs/git-clone), [pip repeatable installs](https://pip.pypa.io/en/stable/topics/repeatable-installs/), [ACM SIGSIM artifact 평가](https://sigsim.acm.org/conf/pads/2024/blog/artifact-evaluation/). 학회 평가를 모든 내부 프로젝트의 의무로 적용하지 않는다.
