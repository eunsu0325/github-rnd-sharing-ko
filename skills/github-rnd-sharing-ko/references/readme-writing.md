# 팀원이 시작할 수 있는 README

## 근거 수집과 독자

실제 표시되는 README 위치와 기존 문체부터 확인한다. GitHub는 `.github`, root, `docs` 순으로 README를 선택하므로 다른 파일을 고치고 첫 화면이 바뀌었다고 보고하지 않는다.

코드 검토자, 처음 실행할 동료, GPU 실험자, 기여자의 경로를 구분한다. 이미 주어진 독자·언어·대상을 재질문하지 않는다. 다음 자료 중 필요한 것을 읽는다.

- 목적과 현 상태: 기존 README, 설계 요약, 결과 기록.
- 설치: manifest/lockfile, 공식 설치 안내, 지원 환경, CI. CI 설정과 실제 통과는 다른 증거다.
- 실행: 실제 entrypoint의 help/인자, 작은 입력·설정, 출력 생성 코드.
- 검증: 로그·지표·환경·코드/자산 revision. 과거 관찰과 이번 실행을 구분한다.
- 협업: 적용되는 AGENTS.md, CONTRIBUTING, PR template, 실제 팀 관례.

버전 요구와 실제 검증 버전도 구분한다. `Python >=3.10`은 모든 해당 환경에서 시험했다는 뜻이 아니다. 인터페이스 의사코드를 복사 실행 가능한 Quick Start로 소개하지 않는다.

## 독자의 판단 순서

다음은 선택 기준이며 고정 목차가 아니다.

| 질문 | 제공할 내용 |
|---|---|
| 무엇에 쓸 수 있나? | 개발 목적·대상 작업·현재 가능한 동작 |
| 어디까지 확인됐나? | 검증한 기능·환경·기준 버전·주요 제한 |
| 내 환경에서 시작할 수 있나? | 필요한 런타임/GPU/시뮬레이터·권한·자산 |
| 가장 작은 실행은? | clone → 설치/설정 → 자산 → 한 가지 최소 실행 |
| 성공했는지 어떻게 알까? | 실제 관찰한 출력·파일·필드·확인 기준 |
| 실패하거나 더 쓰려면? | 주요 오류·상세 사용·기여·도움·출처 링크 |

개요 뒤에서 빠른 시작을 찾기 쉽게 한다. 환경 제약·큰 다운로드 등 핵심 선행 조건은 명령보다 앞에 둔다. 긴 배경·환경 예외·전체 API·연구 일지는 필요에 따라 상세 문서로 연결한다. 코드 트리는 중요한 진입점만 보여준다. Git 입문 강의를 README 전체에 삽입하지 않는다.

## 명령과 정상 결과

명령의 실행 위치, shell/OS, 필수 인자를 적고 실제 존재하는 module·script·config를 쓴다. 공식 설치 방식과 사용자가 선택한 환경을 우선한다. 사용자 실행과 기여자용 editable/dev 설치가 다르면 분리한다. 필요성을 확인하지 않고 venv/Conda/uv/Docker를 모두 제시하지 않는다.

서버/로컬, headless/GUI, offline/SIM/실물 경로에 이름을 붙인다. 기본 quickstart에는 실제 로봇 동작을 넣지 않는다. 첫 실행에 불필요한 전체 데이터·대형 학습을 요구하지 않는다. 자산이 없으면 가능한 작은 실행과 실행할 수 없는 기능을 구분한다.

실행 가능한 명령과 값 치환이 필요한 예제를 구분한다. 저장소 URL이 없으면 실제 주소를 지어내지 않고 미확정이라고 표시한다. 이미 파일을 가진 사람의 실행 경로는 계속 제공할 수 있다. 비밀값 없는 설정 예시를 사용하며 개인 절대경로·캐시를 전제하지 않는다.

정상 결과를 명령 옆에 둔다. 로그 문장보다 결과 파일의 의미·값이 중요하면 확인 방법을 설명한다. 관찰한 출력이 없으면 그 사실을 적고 성공 로그를 만들어내지 않는다. 확률적 실험의 허용 오차·반복 조건은 근거가 있을 때만 적는다.

## 문서별 책임과 마감

README는 진입점, CONTRIBUTING은 개발 환경·검증·기여 절차, PR은 이번 변경의 문제·결과·실제 검증, AGENTS.md는 AI 코드 작업 지침이다. 작은 프로젝트는 README 하나로 충분할 수 있다. 역할을 나눈다는 이유로 파일을 자동 양산하지 않는다. 사람이 시작할 필수 절차를 AI 전용 파일 안에만 숨기지 않는다.

기존 LICENSE·기여 경로를 짧게 연결할 수 있다. 라이선스 섹션을 항상 없애거나 MIT badge를 항상 넣지 않는다. 유지관리자·응답 기한·지원 버전을 사실 없이 약속하지 않는다.

내부 링크/작은 이미지는 문서 기준 상대 경로를 사용하고 대소문자·추적 상태·렌더링을 확인한다. 근거를 고정하는 연구 인용은 commit permalink로 연결한다. badge는 실제 상태/링크가 있을 때만 쓴다. GUI 그림에는 SIM/replay/실물 등 무엇을 보여주는지 적는다.

실행 가능하면 문서 순서대로 명령과 결과를 확인한다. 링크 검사와 렌더링 성공은 실행 성공과 구분한다. CLI·설정·자산 위치가 바뀌면 README도 갱신한다.
